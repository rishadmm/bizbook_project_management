# Subcontractor invoice detail, attachments, PDF, ERP-ready export (build contract)

Today `sub_invoices` is a single row of totals shown in a table (project Invoices tab, `/invoices`). Goal: clicking an invoice opens a **full invoice document** as the subcontractor submitted it, with line items, VAT, deductions, certification, approvals, linked progress and **attachments**, plus a **professional PDF**. The data must be shaped so it can later be pushed to the BizBook ERP (AP invoice).

## 1. Data (migration, bump SCHEMA_VERSION; keep existing columns)
- `sub_invoices` new columns: `sub_invoice_ref` (the subcontractor's own invoice number), `currency` (default 'AED'), `vat_rate` (default 5), `subtotal`, `vat_amount`, `gross_amount`, `retention_percent`, `advance_recovery_percent`, `previous_certified` (cumulative certified before this invoice), `submitted_by_name`, `submitted_by_email`, `submitted_at`, `due_date` (from assignment payment terms), `reviewed_by`, `certified_by`, `certified_at`, `payment_ref`, `payment_method`, `erp_doc_no`, `erp_sync_status` ('not_synced'|'queued'|'synced'|'failed', default 'not_synced'), `erp_synced_at`, `erp_error`.
- New table `sub_invoice_lines`: id, invoice_id (FK cascade), line_no, item_code (BOQ/stage ref), description, unit, contract_qty, rate, prev_qty, this_qty, cum_qty, amount (this_qty × rate), certified_qty, certified_amount, remarks, stage_id (nullable).
- Backfill existing rows in the migration: one line per invoice built from the assignment/stage (qty = claimed_percent × assignment qty, rate from assignment contract value ÷ qty), vat 5%, gross = subtotal + VAT; keep claimed_amount = gross for consistency, or document the convention in docs/FOUNDATION.md. Be consistent everywhere: **claimed (gross incl. VAT) → certified → less retention → less advance recovery → net payable**.
- Attachments use the existing `attachments` table with `entity_type = 'sub_invoice'` (add it to EntityType if missing) and categories: `tax_invoice` (subcontractor's signed invoice copy), `measurement_sheet`, `progress_photos`, `timesheet`, `delivery_note`, `other`.
- Queries in `src/features/invoices/queries.ts`: `getInvoiceDetail(id)` returning the invoice + lines + subcontractor (legal name, address, TRN `tax_no`, bank, IBAN masked except last 4), project, client, assignment (contract value, payment terms, retention %), stage(s), progress reports in the period, previous invoices on the same assignment (for the cumulative statement), attachments, approval request, activity.

## 2. Invoice detail page `/invoices/[id]`
- Permission `invoices/view` + `requirePage`. Breadcrumb Projects › PRJ… › Invoices › SC-…
- Entry points: invoice number in the project Invoices tab and in `/invoices` becomes a link (whole row clickable); approvals inbox item for `sub_invoice` links here; portal invoice links stay in the portal.
- **Header bar**: invoice no + sub's ref, status badge, Portal badge if source = portal, subcontractor, project; actions moved/shared from tabs3 (Review, Certify, Request approval, Re-certify, Pay, Reject — same server actions and permission checks; extract the forms into a shared `src/features/invoices/components/` module and reuse in tabs3), plus **Download PDF**, **Print**, **Copy link**.
- **Main column: "paper" document view** (white A4-like card, BizBook styling): subcontractor letterhead block (name, address, TRN, contact) → "TAX INVOICE" title, invoice no/date/due date/period → Bill to (tenant company from settings: name, address, TRN — add settings keys `company_address`, `company_trn` with seed values) → project/contract reference, stage, PO/subcontract no → **line items table** (item, description, unit, contract qty, previous, this period, cumulative, rate, amount) → subtotal, VAT 5%, gross → **certification block**: certified qty/amount per line (highlight lines where certified < claimed, with remarks), less retention (x%), less advance recovery, **net payable**, amount in words (AED … only) → payment block (paid amount, date, method, ref) → signatures strip (Submitted by, Reviewed by, Certified by, Approved by with dates from the approval trail).
- **Right column**: KPI mini cards (Claimed, Certified, Net payable, Paid, Outstanding); **Attachments** card: grouped by category, file icon, size, uploader, date; PDF and images open in an in-page **viewer modal** (PDF in iframe, images in a lightbox with next/prev), download button; upload (if invoices/edit) with category select; **Approval panel** (existing ApprovalPanel); **Cumulative statement** for the subcontract (all invoices on the assignment: claimed/certified/paid, running % of contract value with a progress bar); **Linked progress reports** for the period (date, qty, verified status, links); **Activity** timeline; **ERP** card: sync status pill, ERP doc no, "Preview ERP payload" (shows the JSON from §4 in a modal) — the "Send to ERP" button is present but disabled with tooltip "ERP connection not configured".
- Responsive: single column below 1024px. Keep visual language from THEME_SPEC.md.

## 3. PDF
- Library: `@react-pdf/renderer` (pure JS, server-side; add to serverExternalPackages if needed). Route handler `GET /invoices/[id]/pdf` (authenticated via `lib/auth.ts`, `invoices/view`); `?download=1` sets `Content-Disposition: attachment; filename="<invoice_no>.pdf"`, else inline.
- Layout (A4, Manrope registered from a local font file in the repo, fallback Helvetica): header with **tenant company** logo-mark/name + "Subcontractor Invoice — Payment Certificate", BizBook violet accent bar; two-column party blocks (Subcontractor / Bill to) with TRNs; meta grid (invoice no, sub ref, date, period, due date, project, subcontract, stage); line items table with zebra rows and repeating header across pages; totals box (subtotal, VAT, gross, certified, retention, advance recovery, **net payable** highlighted), amount in words; certification remarks; approval trail table (level, approver, decision, date, comment); attachments list (name, category); signature boxes; footer on every page: "Generated by BizBook Project · <timestamp> · Page x of y" and a status watermark for non-final states (DRAFT / UNDER REVIEW / REJECTED; PAID shows a green PAID stamp).
- Must render correctly for long invoices (≥ 25 lines → multi-page).

## 4. ERP readiness (no real integration yet)
- `src/features/invoices/erp.ts`: `toErpPayload(detail)` → stable, documented JSON (AP invoice): header (supplier code = subcontractor id/trade license, supplier TRN, invoice no/ref/date/due, currency, project/cost-centre code, subcontract no), lines (account hint "Subcontract cost", project/stage cost codes, qty, rate, net, VAT code `SR5`, VAT amount), deductions (retention payable, advance recovery), totals, attachments (name, category, sha256, url), approvals, source system ids. Version field `schema: "bizbook.ap_invoice.v1"`.
- `GET /api/erp/invoices/[id]` returns the payload (auth + `invoices/view`). Document fields and mapping in `docs/ERP_INTEGRATION.md` (incl. the planned push flow: approved → queued → synced, idempotency key = invoice id + version).

## 5. Portal (subcontractor submission)
- The portal invoice form gains: sub invoice ref, line items (pre-filled from the assignment's stage/BOQ with previous cumulative qty; sub enters this-period qty; rate read-only), VAT auto, and **multiple attachments with category** (tax invoice copy required). Server validates and computes totals; stores `submitted_by_*`, `submitted_at`. Internal "Record invoice" form gets the same line-item editor.

## 6. Seed
- Every invoice has 1–6 realistic lines (e.g. "Trenching & ducting 2×110mm HDPE — km", "Handhole installation — nr", "Cable pulling — m", "Reinstatement — m²"), VAT 5%, retention 10%, advance recovery where the assignment had an advance, and **attachments with real files** written into the uploads dir: a generated **subcontractor tax invoice PDF** in the sub's own simple style (different from ours), a **measurement sheet PDF**, 2–4 **site photo images** (generated, e.g. SVG/PNG with a site-like illustration + caption/date stamp), and a timesheet on some. At least one long invoice (≥ 25 lines) for multi-page PDF. Some invoices have certified < claimed on certain lines with remarks. Keep `npm run check:demo` passing and extend it: every invoice has ≥1 line and ≥1 `tax_invoice` attachment whose file exists on disk.
