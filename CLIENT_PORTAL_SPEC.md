# Client Portal — read-only project reporting for customers (build contract)

Goal: exactly like the subcontractor portal (PORTAL_SPEC.md), but for **clients** (`/clients/[id]`): internal staff create credentials, each client gets its **own URL**, and client users sign in to a **read-only** portal with dashboards, the live map and all reports about **their** projects. Clients can never create, edit, upload or delete anything (only their own password / sessions).

Read first: PORTAL_SPEC.md (mirror its patterns), THEME_SPEC.md, MAP_SPEC.md, DEMO_DATA_SPEC.md, docs/FOUNDATION.md, README.md, `src/lib/portal-auth.ts`, `portal-perms.ts`, `portal-core.ts`, `src/features/portal-admin/**`, `src/app/p/[slug]/**` (shell, login, account), `src/features/ops-map/**`, `src/app/(main)/clients/**`, `src/features/clients/**`, `src/app/api/files/[id]/route.ts`, `src/middleware.ts`.

## 1. Identity & security (separate from internal users AND from subcontractor portal users)
- Migration (bump SCHEMA_VERSION): `clients.portal_slug` (unique), `clients.portal_enabled` (0/1), `clients.portal_show_subcontractors` (0/1, default 1), `clients.portal_show_financials` (0/1, default 1).
- Tables mirroring the subcontractor ones: `client_users` (id, client_id FK, name, email unique per client, phone, job_title, role `admin` | `viewer`, password_hash, status, must_change_password, failed_attempts, locked_until, last_login_at, password_changed_at, created_by, created_at, `project_scope` JSON null = all the client's projects), `client_sessions` (token SHA-256 hash, `impersonated_by`), `client_auth_events`.
- Cookie `bbp_client` (httpOnly, sameSite lax, path `/`), 12 h / remember-me 30 d, lockout 5 failures → 15 min, forced change on first login and after reset. Reuse `lib/password.ts`.
- `src/lib/client-portal-auth.ts`: `getClientSession()`, `requireClientUser(slug)`. **Client id always from the session.** Slug mismatch → redirect to own portal. Every query filtered by `projects.client_id = session.client_id` (+ project_scope). Other client's project id → 404. Internal session never grants client-portal access and vice versa; subcontractor portal session never grants it either.
- Where sensible, extract shared helpers (lockout, token, password checks, slug rules, credentials card, user table) into generic modules used by both portals — **without changing the subcontractor portal's behaviour** (its tests must still pass). If extraction is risky, mirror instead.
- **Read-only by construction:** the client portal has no server actions except login, logout, change password, sign out other sessions. No forms, no upload inputs, no "Copy portal link"/edit buttons from reused components (pass a `readOnly` prop or build client variants). Exports (CSV) and Print/PDF are allowed (read only).
- Roles: `admin` (can see the Team page listing their colleagues, read only — user management stays internal) and `viewer`. Both read-only.
- **Data hygiene — never send to the browser:** internal costs (AC, CPI, budgets, margins), subcontract values, subcontractor invoices/payments/bank data, internal approval trails, internal notes/rejection reasons, unverified or rejected progress reports, other clients' projects. Filter **server side** before serialising (the map payload too). Subcontractor names only if `portal_show_subcontractors = 1` (else "Contractor crew A/B"). Contract value / value of work done only if `portal_show_financials = 1`.
- `/api/files/[id]`: also accept a valid client session, but only for attachments of **verified** progress reports and project-level attachments of that client's visible projects. Otherwise 403.

## 2. Internal side: `/clients/[id]` → tabs (Overview | **Portal access**)
Permission: new action `portal` on module `clients` (permissions.ts + role defaults: admin, super admin and roles that edit clients/projects as PM/director).
Same as the subcontractor Portal access tab: portal URL card `http://<host>/c/<slug>` (copy, open, edit slug, enable/disable), **visibility switches** (Show subcontractor names, Show financials), users table with row actions (reset password, enable/disable, unlock, sign out sessions, edit role & project scope, delete if never logged in), Add user modal (auto temp password, must-change default on), one-time **credentials card** (Copy all / Print, "shown only once", disabled "Email credentials"), login activity, **Open portal as client** (read-only impersonation, amber banner, audited). Clients list: column "Portal: Active (n users) / Off". Clients without projects: tab shows an empty state explaining the portal needs at least one project.

## 3. Client portal `/c/[slug]/...` (BizBook look, own shell like `/p`)
- **Login `/c/[slug]/login`**: split layout, left panel "Client Portal", client name, "Project reporting by Al Noor Infrastructure LLC" (tenant name from settings), benefits (live progress, map, reports). Forgot password → "contact your Al Noor project manager" with PM name/phone. Forced password change page.
- **Shell**: dark sidebar with client name + "Client Portal · BizBook"; nav: Dashboard, Projects, Live map, Reports, Photos, Issues & delays, Team (admin), My account. A small "Read-only access" pill in the topbar. Mobile off-canvas nav.
- **Dashboard**: KPI tiles (active projects, overall % complete weighted, on track / at risk / behind counts, total length km & completed km, open issues, worst projected slip, [financials on] total contract value + value of work done); **portfolio map** (reuse ops-map MapCanvas with only their projects, health colours, plan vs actual); per-project health cards (RAG, actual vs planned bar, planned vs projected finish, slip); portfolio S-curve planned vs actual; delays by cause (client-safe categories); upcoming milestones (stage planned ends in next 60 d); recent verified progress feed with photo thumbnails.
- **Projects** list (card/table toggle, RAG/status filters) → **Project detail `/c/[slug]/projects/[id]`** with tabs: Overview (header, KPIs, forecast card planned vs projected finish, progress ring), Map (project map plan vs actual), Schedule (stages/segments table + mini Gantt/line-of-balance: planned bar, actual, projected extension), Progress (S-curve, weekly progress table from **verified** reports only, quantities done vs total per stage), Photos (gallery from verified reports, lightbox), Issues & delays (issue title, status, responsibility category, impact days, dates — no internal blame text beyond the responsibility category), Reports (shortcuts to §Reports for this project).
- **Live map `/c/[slug]/map`**: reuse the Live Ops Map app (OpsMapApp) in a **client mode**: only their projects, colour modes Health / Delay cause / Staleness (+ Subcontractor only if names visible; **no Cost mode**), time machine & forecast, project drawer without costs, segment card without invoices/portal-link/internal buttons. Full screen + TV mode allowed.
- **Reports `/c/[slug]/reports`**: printable report pages (print CSS, "Print / save as PDF") + CSV export: (1) Project progress report (per project or all, as of date picker: summary, RAG, stage table, S-curve, photos of the period), (2) Schedule & forecast report (planned vs projected finish per stage, slip), (3) Issues & delays report (filter by status/responsibility/date), (4) Monthly progress summary (select month: quantities done, % gained, manpower totals if available, key photos). Use react-pdf only if cheap; otherwise print CSS is fine.
- **Photos**: gallery across projects with filters (project, stage, date range).
- **Issues & delays**: list with filters, read-only detail.
- **Team** (admin role): list of colleagues with role and last login (read only; "Contact Al Noor to add users").
- **My account**: profile (read-only), change password, active sessions (sign out others).
- Every page is read-only: no buttons that modify data. Empty states everywhere.

## 5. Quality
- tsc, lint, calc.check, check:demo, full e2e pass (subcontractor portal tests unchanged and green). New `tests/e2e/client-portal.spec.ts`:
  1. Internal admin creates a client user on `/clients/<id>?tab=portal` → credentials card → login at `/c/<slug>/login` → forced change → dashboard shows only that client's projects.

  5. Disabled portal / disabled user / lockout; impersonation is read-only with the banner.
